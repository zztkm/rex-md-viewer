# rex md viewer

Rex で Markdown ファイルをプレビューするためのツール。

参考: https://github.com/almonk/rexpad.git

## インストール

ビルドには Go 1.27 以降が必要です。
表示には Kitty Graphics Protocol 対応の端末が必要で、分割表示には Rex と `rex` CLI を使用します。
日本語を表示する場合は、日本語対応フォントも必要です。
初期版の実機確認対象は macOS の Rex です。
ブラウザ、Web サーバー、Node.js は不要です。

```bash
go install github.com/zztkm/rex-md-viewer@latest

# または、このリポジトリからビルドする
make build
./bin/rex-md-viewer --help
```

`go install` のインストール先（通常は `~/go/bin`）を `PATH` に追加してください。
開発中のバイナリを利用する場合は、以下の `rex-md-viewer` を `./bin/rex-md-viewer` に置き換えます。

## 使い方

```bash
# 右側にプレビューを開く。繰り返しても同じ Viewer を再利用する
rex-md-viewer view README.md

# 現在の端末に表示する（q または Ctrl-C で終了）
rex-md-viewer view --in-place README.md

# 分割表示を閉じる
rex-md-viewer hide README.md

# Rex に接続せず PNG を生成する
rex-md-viewer render -o preview.png testdata/sample.md

# Agent Skill をインストールする
rex-md-viewer skill install --dir ~/.pi/agent/skills
```

### フォントの設定

rexpad と同様に、環境変数で本文と太字のフォントを個別に設定できます。
Rex の端末設定のフォントを引き継ぐ方式ではありません。

```bash
export REX_MD_VIEWER_FONT="/path/to/regular.ttf"
export REX_MD_VIEWER_FONT_BOLD="/path/to/bold.ttf"
rex-md-viewer view README.md
```

選択順は本文と太字それぞれについて、CLI オプション → 環境変数 → SF Pro Text → Inter → 同梱の Go フォントとします。
未指定時の基本フォントの選び方は rexpad に合わせます。

| 用途 | CLI オプション | 環境変数 | 最終フォールバック |
| --- | --- | --- | --- |
| 本文 | `--font PATH` | `REX_MD_VIEWER_FONT` | Go Regular |
| 見出しと太字 | `--font-bold PATH` | `REX_MD_VIEWER_FONT_BOLD` | Go Bold |

TTF、OTF、TTC に対応し、フォント名ではなくファイルパスを指定します。
SF Pro Text は `/Library/Fonts` と `~/Library/Fonts` の静的 OTF、Inter は Linux の既知のパスを探索します。
環境変数のパスが存在しない場合や読み込めない場合は、rexpad と同様に次の候補へ進みます。
一方、CLI で明示したパスの不備はエラーにします。
相対パスは呼び出し元の作業ディレクトリを基準に解決し、分割先にも解決済みの設定を渡します。
既存 Viewer のフォントを変更する場合は `hide` してから開き直してください。
`REXPAD_FONT` と `REXPAD_FONT_BOLD` 自体は参照しません。

基本フォントで描けない文字は、Noto Sans JP、macOS のヒラギノ、Linux の Noto Sans CJK など、既知のパスの日本語フォントで文字ごとに補います。
漢字、ひらがな、カタカナを基本フォントでもフォールバックでも描けない場合は、設定方法を示してエラーにします。
このため、同梱 Go フォントだけでも英語の文書は表示できますが、日本語の文書には日本語フォントが必要です。
日本語フォントは同梱せず、Go Regular、Go Bold とコードの ASCII 文字用の Go Mono のみを同梱します。

本文は画像として表示するため、端末標準の文字選択、コピー、検索は使えません。
自動更新は Markdown 本体が対象で、ローカル画像だけを変更した場合は Viewer で `r` を押してください。

## 要求

- Agent SKILL を提供する
- Go で実装する
- rexpad のように Markdown を HTML っぽく描画してそれを Terminal に表示する
- ファイルの変更を検知して Viewer を自動更新する

## 仕様

以下は初期版の仕様とする。
要求に明記されていない動作は、初期版の設計判断として定める。

### 利用環境と実装方針

- コマンド名を `rex-md-viewer` とし、Go で実装する。
- 初期版の動作確認対象は macOS 上の Rex とする。
- Markdown を解析してレイアウトし、画像として描画する。
  画像は Kitty Graphics Protocol で端末に表示する。
- 「HTML っぽく描画する」とは、見出しの文字サイズ、余白、背景色、罫線などを使い、ブラウザの Markdown プレビューに近い見た目にすることを指す。
  HTML/CSS の互換実装は行わず、ブラウザ、Web サーバー、Node.js を実行時の依存にしない。
- Rex のペイン操作には `rex` CLI を利用する。
  Rex の内部ソケットへ直接アクセスしない。
- `view` は既定で Rex の分割ペインに表示し、`--in-place` 指定時は現在の端末で動作する。
  分割ペインへの表示と `hide` は Rex 内からの実行を必要とする。
  Rex 以外の端末での動作保証と、画像表示に対応しない端末向けのテキスト表示は初期版の対象外とする。

### CLI

```text
rex-md-viewer view [OPTIONS] FILE
rex-md-viewer hide FILE
rex-md-viewer render [OPTIONS] -o OUTPUT.png FILE
rex-md-viewer skill install --dir DIR [--force]
rex-md-viewer skill show
rex-md-viewer --help
rex-md-viewer --version
```

| コマンド | 動作 |
| --- | --- |
| `view` | 既定で Rex の分割ペインに Viewer を開き、既存の同一 Viewer があれば再利用する。`--in-place` 指定時は現在の端末で起動する。いずれもファイルを監視する。 |
| `hide` | 呼び出し元のペインから分割表示で開いた、指定ファイルの Viewer を閉じる。対象がなければ成功として終了する。利用者が現在の端末で直接起動した Viewer は対象外とする。 |
| `render` | ファイルを一度だけ読み込み、文書全体を PNG に出力する。端末と Rex 接続を必要としない。 |
| `skill install` | 指定した Skill ディレクトリの下に `rex-md-viewer/SKILL.md` を配置する。 |
| `skill show` | 同梱する `SKILL.md` を標準出力に表示する。 |

利用例は次のとおりとする。

```bash
# 右側のペインでプレビューする（既定）
rex-md-viewer view README.md

# 現在の端末でプレビューする
rex-md-viewer view --in-place docs/design.md

# 下側に開き、分割領域の 40% を使う
rex-md-viewer view --below --ratio 40 docs/design.md

# 表示結果を画像として確認する
rex-md-viewer render --width 1000 --theme light -o preview.png README.md

# pi 用の Skill を配置する
rex-md-viewer skill install --dir ~/.pi/agent/skills
```

#### オプション

| オプション | 対象 | 既定値と動作 |
| --- | --- | --- |
| `--in-place` | `view` | 分割ペインを開かず、現在の端末で表示する。既定では指定なし（右側の分割ペインに表示）。 |
| `--below` | `view` | 右側ではなく下側に分割する。 |
| `--ratio PCT` | `view` | 新しいペインの割合。既定値は `40`、指定範囲は `1`〜`99`。 |
| `--theme terminal\|light\|dark` | `view` | 既定値は `terminal`。端末の前景色と背景色を基準に配色する。 |
| `--theme light\|dark` | `render` | 既定値は `light`。 |
| `--font PATH` | `view`, `render` | 本文フォントのファイルパス。`REX_MD_VIEWER_FONT` より優先する。未指定時の選択順は「フォントの設定」に従う。 |
| `--font-bold PATH` | `view`, `render` | 見出しと太字用のフォント。`REX_MD_VIEWER_FONT_BOLD` より優先し、本文とは個別に選択する。 |
| `--width PX` | `render` | 出力画像の幅。`1`〜`8192` の整数を指定し、既定値は `1000` ピクセル。 |
| `-o PATH` | `render` | 出力先。必須。既存ファイルは上書きするが、入力 Markdown 自体への上書きは拒否する。 |
| `--force` | `skill install` | 既存の `SKILL.md` を上書きする。未指定時は同一内容なら成功、異なる内容ならエラーとする。 |

`--in-place` と `--below` または `--ratio` を併用した場合は、用途が矛盾するため CLI の使用方法の誤りとして終了する。

分割表示では、起動先で `view --in-place` を実行し、指定された描画オプションと入力ファイルの絶対パスを明示的に引き継ぐ。
この場合のペインの登録と再利用は、呼び出し元の `view` が管理する。
既存 Viewer の再利用時はその設定を維持し、設定変更には `hide` と `view` による再起動を使う。
利用者が `--in-place` を指定して直接起動する場合は、分割表示の Viewer の再利用や状態ファイルへの登録は行わず、現在の端末で独立した Viewer として動作する。

### 入力ファイル

- 1 つの Viewer が扱う Markdown ファイルは 1 つとする。
- UTF-8 の通常ファイルを入力とし、拡張子による制限は設けない。
  不正な UTF-8、ディレクトリ、読み取りできないパスはエラーとする。
- 相対パスはコマンド実行時の作業ディレクトリを基準に絶対パスへ変換する。
  パス中の `.` と `..` は正規化するが、シンボリックリンクは解決せず、そのパスを継続して読み込む。
- 空白、日本語、シェルの特殊文字を含むパスを扱えるようにする。
  `--` 以降はオプションとして解釈せず、`-` で始まるファイル名も指定できるようにする。
- 空のファイルはエラーにせず、本文領域に「空のファイル」と表示する。
- 標準入力、URL、ディレクトリ全体のプレビューは初期版の対象外とする。

### Markdown の対応範囲

CommonMark を基本とし、表、タスクリスト、取り消し線、自動リンクを追加する。
GitHub Flavored Markdown 全体との互換性は保証しない。

| 要素 | 表示方針 |
| --- | --- |
| 見出し `h1`〜`h6` | 階層に応じて文字サイズ、太さ、前後の余白を変える。 |
| 段落、改行 | ペイン幅に合わせて折り返す。通常の改行は CommonMark の規則に従う。 |
| 強調、太字、取り消し線 | 字形または装飾線で区別する。 |
| 順序付きリスト、順序なしリスト | 番号またはマーカーと字下げを表示し、入れ子に対応する。 |
| タスクリスト | 未完了、作業中、完了を専用のチェックボックスで描画する。`[~]` は作業中の独自拡張とする。操作による状態変更は行わない。 |
| 引用 | 左側の罫線と字下げで区別する。 |
| インラインコード | 等幅表示と背景色で本文から区別する。 |
| コードブロック | 空白と改行を保持し、等幅表示と背景色を使う。フェンスの言語指定に応じて構文を色分けする。長い行は視覚的に折り返す。 |
| 水平線 | 横罫線を描画する。 |
| 表 | セルの境界とヘッダーを区別し、セル内を折り返す。Markdown で指定された列の配置を反映する。 |
| リンク | リンク文字列を色と下線で区別する。リンク先への移動は初期版の対象外とする。 |
| 画像 | ローカルの PNG、JPEG、GIF を縦横比を保って本文幅内に表示する。GIF は先頭フレームのみ表示する。 |
| 生の HTML | タグを含むソースを文字列として表示し、実行や HTML としての描画はしない。 |

画像の相対パスは、Markdown ファイルのあるディレクトリを基準に解決する。
画像を読み込めない場合と、リモート URL や未対応形式の場合は、代替テキストと読み込めない理由を表示し、本文の表示は続行する。
HTTP リクエストによる画像やフォントなどの取得は行わない。

数式、Mermaid、脚注、目次生成、YAML front matter の専用処理は初期版の対象外とする。
未対応の独自記法は、通常の Markdown として解析する。

#### コードブロックのハイライト

フェンスの先頭に `go`、`python`、`bash`、`javascript`、`json`、`yaml` などの言語を指定すると、Chroma で解析してキーワード、文字列、コメント、数値などを色分けする。
`py`、`sh`、`js` など、Chroma が対応する別名も使用できる。
フェンスの言語名より後の追加情報は、言語の判定に使用しない。

- `view` と `render` の両方でハイライトする。
- コードの背景色は維持し、背景の明るさに応じて GitHub のライト用またはダーク用の文字色を選ぶ。
  `terminal` テーマでは端末から取得した背景色を基準にし、配色変更時も更新する。
- ハイライトで変更するのは文字色だけとし、字形、空白、改行、折り返し位置は変更しない。
- 言語指定なし、未対応の言語、インデントによるコードブロックは単色で表示する。
  言語の自動推定は行わず、インラインコードと生の HTML もハイライトしない。
- 1 ブロックの本文が 256 KiB を超える場合や、構文解析に失敗した場合も、内容を省略せず単色で表示する。

#### リストの配置

- リストにはマーカー列と本文列を設け、マーカー列の幅は、そのリスト内で最も幅の広いマーカーに合わせる。
- 通常のリストでは、マーカー列の右端から本文までの間隔を本文の文字サイズの半分とする。
  文字サイズが 16px、拡大率が 1 の場合は 8px とする。
  TODO 項目だけのリストには、後述の TODO 専用の間隔を使う。
  通常の項目と TODO が混在するリストでは、本文の開始位置を揃えるため通常のリストの間隔を共有する。
- 通常の点とタスクリストのチェックボックスは、マーカー列の左端に揃える。
  タスクリストに、表示しない点のための追加の字下げは設けない。
- 順序付きリストの番号はマーカー列の右端に揃え、番号だけを途中で折り返さない。
- 折り返し行、明示的な改行後の行、同じ項目内の後続の段落は本文列の先頭に揃える。
- 入れ子のリストは、親の本文列の先頭を子のマーカー列の左端とする。
- 表示幅が不足する場合はマーカーを縮小する。
  最小サイズでも本文と横に並べられない場合は、マーカーの下に本文を配置する。

#### TODO の表現

未完了、作業中、完了の項目表現は rexpad に合わせる。
見出し、文書全体の外側余白、入れ子の構造は、通常の Markdown としての表示を維持する。

- `[ ]` はグレーの枠を持つ角丸の空欄として表示する。
- `[~]` はアクセント色の角丸枠と淡い行背景で表示し、本文の末尾に動く3点を付ける。
  作業中の本文は通常の文字色を維持する。
- `[x]` と `[X]` はアクセント色の角丸ボックスと白いチェックマークで表示する。
  アクセント色が明るい場合は、チェックマークに背景色を使ってコントラストを確保する。
- 完了した項目の本文はグレーにする。
  完了状態だけでは取り消し線を付けないが、Markdown に明示された取り消し線は維持する。
- 太字、リンクの下線、インラインコードなどの装飾は維持する。
  完了した項目ではリンクも含めて文字色をグレーにし、入れ子の項目にはその項目自身の状態を適用する。
- 同じ項目内の後続の段落にも TODO の文字サイズと状態に応じた文字色を適用する。
  コードブロック、画像、子のリストなどは、それぞれの Markdown 要素として描画する。

基準寸法は次のとおりとし、表示時に拡大率を適用してピクセル単位に丸める。

| 対象 | 基準値 |
| --- | --- |
| 本文の文字サイズ | 14pt |
| チェックボックス | 一辺 12pt、角丸半径 3pt、枠線幅 1pt |
| マーカー列の右端から本文まで | 6.5pt |
| 1 行の項目の高さ | 28pt |
| 同一項目の折り返し行の間隔 | 18pt |

複数行の本文では、2 行目以降の行数に応じて項目の高さを増やす。
#### WIP の記法と表示

`[~]` は GitHub Flavored Markdown にはない独自拡張とする。
他の Markdown ビューアでは、通常のリスト内の文字列として表示される場合がある。

```markdown
- [ ] 未着手
- [~] 作業中
- [x] 完了
```

- リスト項目の最初の段落の先頭にある `[~]` だけを状態マーカーとして認識する。
  マーカーの直後には半角スペースまたはタブを置くか、行末にする。
- コード、エスケープされた記法、通常の本文、項目途中や後続の段落にある `[~]` は状態として扱わない。
- `[>]` と `[/]` は別表記として認識せず、文字列のまま表示する。
- 作業中の背景は、その項目自身の本文段落に適用する。
  入れ子の子項目は各項目の状態に従い、親の作業中の背景を引き継がない。
- 背景は本文の折り返しに合わせて広げ、角丸半径は 6pt、左右の広がりは 6pt、項目の上下の空きは 2pt を基準とする。
- 3点は、その項目の最後の本文段落の末尾に配置する。
  点の直径は 3.5pt、点同士の間隔は 2pt、本文からの間隔は 6pt を基準とする。
  点の領域を確保して本文を折り返し、幅が足りない場合は次の行に配置する。
- 各点の明るさを順番に変えるアニメーションを、1.2 秒周期、各点 0.2 秒ずらし、最大 15fps で更新する。
- アニメーションは3点が画面内に見える場合だけ動かし、文書全体ではなく小さな画像を更新する。
  完了状態への変更やスクロールで3点が見えなくなった場合は更新を止める。
- `render` ではアニメーションの一定のフレームを PNG に出力し、同じ入力と設定から同じ画像を生成する。
- WIP による自動スクロールや、グループの進捗計算とリング表示は行わない。

### レイアウトと端末表示

- 画面はファイル名を示すヘッダー、本文、更新状態を示すステータス領域で構成する。
- 横スクロールを必要としないように、本文を利用可能な幅へレイアウトする。
  日本語と英数字が混在する段落を折り返せるようにする。
- 基本フォントは rexpad と同様に SF Pro Text、Inter、同梱 Go フォントの順で選び、CLI オプションと環境変数で上書きできるようにする。
  不足する文字には日本語フォントを使い、基本フォントとのベースラインを揃えて描画する。
  文書中の漢字、ひらがな、カタカナに対応するフォントがない場合は、`--font` と環境変数の指定方法を示して終了する。
- 端末のセル寸法と表示領域から描画サイズを決定し、高 DPI 環境での文字の可読性を確保する。
- ペインのリサイズ時は幅に合わせて再レイアウトし、高さの変更時は表示範囲を調整する。
- `terminal` テーマでは起動時と実行中に端末の配色を問い合わせ、変更を反映する。
  前景色と背景色に加え、端末のパレットの青（OSC 4 のインデックス 4）をアクセント色として取得する。
  前景色と背景色の取得に失敗した場合は `dark` を使用し、青だけを取得できない場合は既定のアクセント色を使う。
- 新しい画像を配置してから古い画像を削除し、更新時の空白やちらつきを抑える。
- 画像表示のため、端末標準の文字選択、コピー、検索では本文を扱えない。
  独自の検索とクリップボード連携は初期版の対象外とする。

#### Viewer の操作

| キー | 動作 |
| --- | --- |
| `j` / `k`、下矢印 / 上矢印 | 本文の基本行高を基準に下 / 上へスクロールする。 |
| `Space` / `b`、`PageDown` / `PageUp` | 本文の表示領域 1 ページ分、下 / 上へ移動する。 |
| `g` / `G`、`Home` / `End` | 文書の先頭 / 末尾へ移動する。 |
| マウスホイール、トラックパッド | 本文を上下にスクロールする。 |
| `r` | Markdown と参照画像を再読み込みする。 |
| `q`、`Ctrl-C` | Viewer を終了する。 |

終了時はマウス入力、カーソル、raw mode、代替画面を元に戻し、自身が表示した画像を削除する。
`SIGTERM` による終了でも同じ後処理を行う。

### ファイル変更の検知

- Viewer は分割表示と現在の端末への表示のどちらでも、起動時にファイルを表示し、その後は 200 ms 間隔で対象パスを確認する。
- ファイルの内容を比較して変更を判定する。
  更新時刻とファイルサイズが変わらない書き換えも検知する。
  内容が同じ場合は変更検知による再描画を行わないが、手動更新、リサイズ、テーマ変更による再描画は行う。
- エディターが一時ファイルを rename して置き換える保存方式に対応する。
  元のファイル記述子を監視し続けず、対象パスから読み直す。
- 連続した変更は 200 ms の待機時間でまとめる。
  変更が続く間も表示が更新されるように、待機は最大 1 秒で打ち切る。
- 更新後も本文先頭からのスクロール位置を描画上の距離で維持し、文書が短くなった場合は表示可能な範囲に収める。
  編集前と同じ段落を追跡する機能と、末尾への自動追従は初期版の対象外とする。
- 起動後にファイルが削除された場合や読み取りに失敗した場合は、最後に成功した表示を残し、ステータス領域に理由を表示する。
  対象パスの確認を続け、再作成や権限の復旧を検知したら表示を回復する。
- 描画中に新しい変更があった場合は、古い処理結果で最新の表示を上書きしない。
- 参照画像のみの変更は自動検知の対象外とする。
  `r` または Markdown 自体の変更による再描画で読み直す。

### Rex のペイン管理

以下は `view` に `--in-place` を指定しない分割表示と、`hide` に適用する。

- `view` は `$REX_SESSION` と `$REX_BLOCK` を使い、呼び出し元の右側に Viewer を開く。
  `--below` が指定された場合は下側に開く。
- ペインを開く際は `--focus=false` を使用し、呼び出し元のフォーカスを維持する。
- Viewer の識別には、Rex 接続先、セッション ID、呼び出し元のペイン ID、正規化したファイルの絶対パスを使用する。
  同じ組み合わせで `view` を繰り返してもペインを増やさない。
- 別のファイルは別の Viewer で開けるようにする。
  同じファイルでも、呼び出し元のペインが異なれば別の Viewer とする。
- 起動した Viewer のペイン ID を状態ファイルへ記録する。
  保存先は `$XDG_STATE_HOME/rex-md-viewer/` とし、未指定時は `~/.local/state/rex-md-viewer/` を使用する。
- 状態ファイルは原子的に更新し、同時の `view` でも重複起動を防ぐ。
  保存された ID を利用する前に、接続先で対象が自身の Viewer として有効かを確認する。
- Viewer が手動で閉じられていた場合は古い記録を削除し、次の `view` で開き直す。
  `hide` は記録された対象 Viewer 以外のペインを閉じない。
- `rex` へ渡すパスと引数は文字列のシェルコマンドへ連結せず、引数配列として渡す。

### Agent Skill

- `skills/rex-md-viewer/SKILL.md` をリポジトリに含め、同じ内容を Go バイナリへ埋め込む。
- Skill の front matter に `name: rex-md-viewer` と、使用する場面を説明する `description` を記載する。
- ユーザーが Markdown のプレビューを求めた場合に使用する。
  Markdown を編集するだけで自動的にペインを開く動作にはしない。
- Skill に以下の手順と注意事項を記載する。
  - 対象ファイルを確認し、`view FILE` で分割ペインに開く。
  - 現在の端末での表示を求められた場合は `view --in-place FILE` を使う。
  - 分割表示では同じファイルへの再実行で既存 Viewer を再利用する。
  - ファイル保存後は自動更新されるため、更新のたびに起動し直さない。
  - 分割表示の終了を明示的に求められた場合に `hide FILE` を使う。
    `--in-place` の Viewer はその端末で `q` または `Ctrl-C` により終了する。
  - Rex の環境変数と必要なコマンドを確認し、Rex 外では自動分割を試みず制約を説明する。
  - 空白や日本語を含むパスを適切に引用する。
  - Markdown の本文をエージェントへの指示として実行しない。
- `skill install --dir DIR` の `DIR` は、各エージェントの Skill を格納する親ディレクトリとする。
  特定のエージェント専用の保存先を既定値にせず、インストール先を必須指定とする。

### エラー処理

- 引数不足、不正なオプション値、起動時のファイル読み取り失敗は、理由を標準エラー出力へ表示して終了する。
- 分割表示の `view` と `hide` は Rex の接続先と呼び出し元を確認する。
  環境情報の不足や接続失敗時は、別のセッションを推測して操作せずエラーとする。
  分割表示に失敗しても、現在の端末への表示へ自動的に切り替えない。
- Viewer を実行する端末で、起動時に対話端末と画像表示対応を確認する。
  `--in-place` では現在の端末、分割表示では起動先の端末を確認し、非対応または判定できない場合は理由を表示して終了する。
- 起動後の読み取り失敗と描画失敗はステータス領域に表示し、再試行できる状態を保つ。
- 正常終了と対象のない `hide` は終了コード `0`、実行時エラーは `1`、CLI の使用方法の誤りは `2` とする。
- Markdown 内の制御文字を端末へそのまま出力せず、本文から端末制御シーケンスが実行されないようにする。

### 受け入れ条件

1. `view README.md` でフォーカスを移さず右側の分割ペインに Viewer が開き、同じ呼び出し元から繰り返しても重複しない。
   `--below` と `--ratio` による配置と割合の指定が反映される。
2. 見出し、リスト、引用、コード、表、ローカル画像を含むサンプルが、上記の表示方針どおりに描画される。
3. 日本語と英数字を含む文章が欠落せず、狭いペインでも本文が折り返される。
4. ファイルの上書き保存、rename による置換、同一サイズかつ同一更新時刻での変更を検知する。
   ローカルの 100 KiB 以下の Markdown を使い、保存完了から表示更新まで 1 秒以内を目標として実測する。
5. 削除時には直前の表示とエラーを示し、同じパスへの再作成後に表示が回復する。
6. スクロール、リサイズ、テーマ変更が反映され、更新でスクロール位置が不必要に先頭へ戻らない。
7. 空白、日本語、シェルの特殊文字を含むパスを、分割表示の `view`、`view --in-place`、`render`、`hide` で扱える。
8. `q`、`Ctrl-C`、`SIGTERM` で終了した後、端末へ正常に入力でき、Viewer の画像が残らない。
9. `render` が Rex に接続せず PNG を生成し、レイアウト確認に使用できる。
10. `skill install --dir DIR` と `skill show` が、リポジトリに同梱した Skill と同じ内容を提供する。
11. 未対応の端末、存在しない入力、不正なオプションに対して、原因と終了コードを確認できる。
    `--in-place` と `--below` または `--ratio` の併用では終了コード `2` を返す。
12. 自動テストでパス処理、変更検知、CLI の引数処理、Viewer の重複起動防止を検証する。
    描画結果と Rex 連携はサンプル文書を使った目視確認も行う。
13. `view --in-place FILE` はペインを追加せず、現在の端末で表示と自動更新を行う。
    分割表示の Viewer と独立して動作し、`hide FILE` の対象にならない。

### 実装構成と安全上限

- Markdown の解析には goldmark、コードブロックの構文解析には Chroma、フォントと画像の描画には `golang.org/x/image` を使用する。
  Chroma のトークンを既存の画像描画に反映し、HTML や ANSI エスケープによる出力は行わない。
- Go の最低バージョンは `1.27` とする。
- Viewer は文書の描画命令を保持し、表示領域だけを PNG にする。
  スクロール時は表示領域を再描画して送信するため、長い文書全体の巨大なビットマップは保持しない。
- メモリ使用量を抑えるため、Markdown は 8 MiB、描画要素数は 100 万、描画幅は 8192 ピクセルを上限とする。
  文書全体の PNG 出力と端末の表示領域は、それぞれ 33,554,432 画素を上限とする。
- ローカル画像はファイルサイズ 32 MiB、1 枚あたり 16,777,216 画素、レイアウトごとの読み込み合計は 33,554,432 画素を上限とする。
  上限を超えた画像は代替テキストと理由を表示する。
- 上限を超えた Markdown や PNG 出力は、理由を表示してエラーにする。
- rexpad を参考にした端末表示とペイン管理、および依存ライブラリのライセンスは `THIRD_PARTY_NOTICES.md` に記載する。
